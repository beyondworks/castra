# Castra

**코딩 에이전트는 한 걸음을 남기고 멈춘다. Castra가 그 한 걸음이다.**

Castra는 [Claude Code](https://claude.com/claude-code)용 실행 태세 하네스입니다. 규칙 팩 하나, 훅 넷, 스크립트 둘로 이루어져 있습니다. 모델을 똑똑하게 만들지는 않습니다. 능력 있는 모델이 일을 끝내기 직전에 조용히 멈추는 네 자리를 없앱니다.

- 고쳤지만 배포하지 않았다 → 배포는 검증의 일부다
- 작업 도중 컨텍스트 창이 찼다 → 창을 넘겨 살아남는 체크포인트를 남긴다
- 되돌릴 수 없는 명령이 한 글자 앞에 있다 → 실행 전에 등급을 매긴다
- 미결 항목을 남긴 채 턴이 끝난다 → 턴이 끝나지 않는다

## 무엇이 문제인가

강한 모델에게 버그를 맡기면 원인 진단은 대개 정확합니다. 그리고 이런 문장이 돌아옵니다.

> 원인은 큐 핸들러에 있습니다. 상주 서버에 #469가 배포되어야 동작합니다.

진단은 맞습니다. 버그는 그대로 살아 있습니다. 세션이 끝나고, 다음 세션은 아무도 동작을 확인하지 않은 수정을 물려받습니다.

이것은 추론 실패가 아닙니다. 모델은 무엇을 해야 하는지 알고 있었고, 마지막 한 걸음을 다른 사람의 몫으로 분류했을 뿐입니다.

| 모델이 하는 말 | 실제 사실 |
|---|---|
| "먼저 배포되어야 합니다" | 배포는 경계가 아니라 할 일이다 |
| "검증할 윈도우 기기가 없습니다" | `~/.ssh/config`에 접속 가능한 호스트가 있다 |
| "테스트가 통과합니다" | 결함이 살아 있는 동안에도 통과하던 테스트다 |
| "다음 세션에 넘기겠습니다" | 다음 세션은 미검증 수정을 물려받는다 |

## 네 가지 장치

규칙으로 되는 것과 되지 않는 것을 나눈 것이 설계의 핵심입니다. **모델이 읽는 규칙은 실행 시점의 상태를 볼 수 없습니다.** 컨텍스트 압박, 명령의 위험도, 턴 종료 시점의 미결 항목은 프롬프트만으로 알 수 없으므로 훅으로 돌립니다.

1. **태세 팩** — 세션 시작 훅이 전문을 컨텍스트에 직접 넣습니다. 압축 직후에도 다시 넣습니다. 모델이 열어야 하는 파일이 아닙니다. 처음에는 `CLAUDE.md`에 경로만 적어 두었는데, 그 줄이 주입된 세션 10개 중 팩을 실제로 연 세션이 0개였습니다. 모델이 읽기로 선택해야 성립하는 규칙은 효력이 없습니다. 비용은 세션당 약 8,600 토큰입니다. 더 싼 요약본은 이미 있었고, 그 상태에서 읽힌 횟수가 0이었습니다. 27개 절의 내용은 요청형 어투는 실행 지시로 취급한다, 없는 능력은 멈출 이유가 아니라 찾아볼 대상이다, 통과는 주장이므로 감사한다, 그리고 모델마다 기우는 방향이 달라 자기 실패 모드에 해당하는 조항에 가중치를 둔다.
2. **예산 훅** — 세션 기록의 `usage` 값에서 실제 창 점유량을 읽어 두 임계값에서 지시를 주입합니다. 창 크기는 모델 이름과 그 모델이 실제로 도달한 최대 점유량으로 자동 감지합니다.
3. **가드 훅** — 셸 명령을 실행 전에 네 등급으로 분류합니다. 위험 패턴을 검색하는 일과 실행하는 일을 가르되, 명령줄에 실행 구간이 하나라도 있으면 예외를 적용하지 않습니다.
4. **미결 훅** — `.castra/openloops`에 항목이 남아 있으면 턴을 끝내지 않습니다.

## 함께 들어 있는 thinking-map 스킬

Castra는 일의 끝을 다룹니다. 함께 들어 있는 스킬 하나는 일의 시작을 다룹니다. 두 실패가 서로 반대편에 있고 둘 다 실제로 일어나기 때문입니다.

모델에게 문제를 벌려 보라고 하면 평평한 목록이 돌아옵니다. 그럴듯한 선택지 열 개가 관습적인 순서로 늘어서고, 모델은 그중 위쪽 하나를 고릅니다. 그 목록에는 둘을 맞붙여 나온 항목이 하나도 없습니다. 넓히기만 했지 연결하지 않은 것입니다.

`skills/thinking-map/SKILL.ko.md`는 네 단계를 강제합니다.

1. **후보를 적기 전에 축부터 가릅니다.** 판정 기준은 하나입니다. 한 축의 두 항목은 동시에 성립할 수 없어야 합니다. "무료"와 "구독"은 같은 축이고, "무료"와 "기업 대상"은 다른 축입니다.
2. **축마다 최소 넷을 벌리고**, 마지막 하나는 일부러 극단이나 반대를 넣습니다. 익숙하지 않은 항목은 넷째부터 나옵니다.
3. **다른 축의 항목을 맞붙이고, 쌍마다 작동 방식을 한 문장으로 적습니다.** 두 단어를 나란히 놓는 것은 연결이 아니며, 작동 방식을 쓰지 못하는 쌍은 버립니다. 그 다음 조합 둘을 다시 붙여 봅니다. 원래 어느 목록에도 없던 것은 이 2차 연결에서 나옵니다.
4. **기준을 먼저 정한 뒤 쳐내고**, 아깝게 탈락한 하나는 이유와 함께 남깁니다.

무게를 지는 규칙은 둘입니다. 1단계의 직교 판정이 없으면 축이 서로 섞여서 3단계가 같은 목록을 다시 묶는 일로 되돌아갑니다. 3단계의 작동 방식 한 문장이 종합과 나열을 가릅니다.

스킬은 `~/.claude/skills/thinking-map/`에 설치되고 `/thinking-map`으로 부를 수 있습니다. 같은 이름의 스킬이 이미 있으면 설치 스크립트가 건드리지 않습니다.

## 설치

**macOS·리눅스**

```bash
git clone https://github.com/beyondworks/castra.git
cd castra && ./install.sh
```

**윈도우**

```powershell
git clone https://github.com/beyondworks/castra.git
cd castra
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

필요한 것은 파이썬 3뿐입니다. 두 스크립트 모두 `install.py`를 부르는 얇은 껍데기라 실제 동작은 완전히 같습니다. 팩과 스크립트는 `~/.castra/`로, 훅 셋은 `~/.claude/hooks/`로 들어갑니다. 기존 훅은 건드리지 않고 등록만 추가하며 설정 파일은 쓰기 전에 백업합니다. `--dry-run`을 붙이면 무엇이 바뀔지만 보여줍니다.

### 훅을 셸이 아니라 파이썬으로 쓴 이유

Claude Code는 셸 형식 훅을 macOS·리눅스에서는 `sh -c`로 실행하지만, 윈도우에서는 Git Bash로, 그마저 없으면 PowerShell로 실행합니다. 따라서 `.sh` 훅은 이식되지 않고 `$HOME`의 의미도 경우마다 다릅니다.

그래서 Castra는 **exec 형식**으로 등록합니다. Claude Code가 셸을 거치지 않고 인터프리터를 직접 실행하는 방식이라, 셸 차이와 따옴표 처리와 변수 확장이 통째로 빠집니다. 설치기는 인터프리터의 절대 경로를 쓰되 심볼릭 링크를 일부러 따라가지 않습니다. 링크를 따라가면 버전이 박힌 경로가 고정되는데, 그 경로는 다음 패치 때 사라지면서 훅을 조용히 죽입니다.

가드 분류기에 PowerShell 규칙을 함께 넣은 것도 같은 이유입니다. `Remove-Item -Recurse -Force`나 `Format-Volume`은 POSIX 패턴이 하나도 걸리지 않는 표기의 같은 위험입니다.

## 이것이 아닌 것

- **벤치마크 결과가 아닙니다.** 규칙을 명시했을 뿐이고 효과 크기는 측정하지 않았습니다.
- **안전장치 우회가 아닙니다.** 되돌릴 수 있는 작업에서 실행 쪽으로 기울일 뿐, 확인 요구를 낮추지 않고 오히려 하나 더 답니다.
- **마법이 아닙니다.** 팩은 평범한 영어 규칙이고 훅은 300줄 남짓입니다. 설치 전에 전부 읽어 보시기를 권합니다.

영어 문서는 [README.md](README.md)에 있습니다. 라이선스는 MIT입니다.
